class VAR_DECL(combinators.RuleItem):
    entrypoint = combinators.Seq(
        combinators.MatchGroup('types'),
        combinators.MatchToken('IDENT'),
        combinators.Opt(combinators.Ref(VAR_ASSIGN))
        )
    nodeable = True ; requerido para soporte VSIX


    colors: {
        0: "#FFFFFF" ; siempre el primer Token, en este caso, el tipo de MatchGroup encuentre.
        1: "#FFFFFF" ; este sería el color del IDENT
        ... Así sucesivamente, los números mapean colores para los tokens, por lo que podemos meter hasta 100000000 aunque la secuencia solo tenga 3 tokens. Ya que el generador usará los mapas, los mapas no usarán los tokens.
    }

    autocomplete: {
        0: "x = 10" ; completa desde el Token 0, por lo que omitira int.
        1: "= 10"   ; completa desde el IDENT, por lo que omitirá el IDENT al insertar.
        ... Así sucesivamente. Al igual que colors, puedo definir hasta 10000 sin fallos, porque es solamente un mapa.
    }

    suggestions: {
        0: show_names ; debe ser una tupla, función o lambda. Se llamará desde el LSP, y siempre debe retornar una Lista. Es útil para cosas como "import" para mostrar sugerencias de importaciones. En este caso, cuando cuando escriba int me debería ejecutar la función apuntada. Debe ser int + espacio, si no se puede, pues solo al escribir int, pero si se puede detectar el espacio, priorizar el espacio para ejecutar apenas se escriba la palabra.
        ... Igual que los otros, esto es solo un mapa.

    }

    ; se eliminarán docs, ya que no hace falta aquí en RuleItem.

    hints: {
        0: "integer" ; mostraría algo como int integer
    }

    playhints: {
        0: "$TOKEN(0)" ; el lenguaje permitirá acceder a los tokens del propio AST generado, pudiendo insertar datos dinamicamente. En este caso, al hacer click en "integer" insertará int al lado de int; int int
    }

    ; obviamente estos son ejemplos rigidos con un VAR_DECL, en otros casos brillarán. La razón por la que todo debe caer en nodeables, es que es una estructura que agrupa varios nodos con tokens, entonces, al compilar se genera un mapa con todo lo que pide el RuleItem noodeable (como este), e itera por todos sus hijos para ir haciendo merges.

    ; Si no se conoce la cantidad exacta de tokens en el nodo, se pueden usar identificadores especiales: "this" para apuntar al propio token. "this:-1" mira al de atrás, "this:1" mira al de adelante.
